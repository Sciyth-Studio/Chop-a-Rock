# Weather

Plan: `WeatherSystemPlan.md` (approved 2026-10-14, W1-W12). Rules: Master Game Plan §05. Every number is a draft in `WeatherConfig`.

## Rules
- **Clock:** `WeatherClock` (shared, pure). Slot `k` starts at `k * 1800` Unix seconds and lasts 300 s (900 until 2026-10-16, when the user asked for 5 minutes). The event for a slot is a weighted roll seeded by `ClockSeed + k`, so every server agrees without talking. Weights: Sandstorm 35, Hurricane 25, Heat Wave 20, Thunderstorm 15, Eclipse 5.
- **Storm rocks** (user asked 2026-10-16): during an event each per-player rock that spawns (Rush rocks too) has `StormRockChance` (25%) to be a storm rock (`WeatherService:RollStormRock` → `Rock.Weather` = event key, sent as the 5th `RockSpawned` arg; the client sets the rock's `Weather` attribute and `WeatherController` only adds the modifier emitters to rocks whose attribute matches the event). Only storm rocks pay the event's `RockMultiplier` (`GetRockMultiplier(rock.Weather)`, added to the Rush multiplier rather than multiplied since 2026-10-19, see [[Rush Rocks]]); a storm rock left over from an ended event is plain again. When an event starts, `RockService:StartStorm` also turns `StartStormRocksPerZone` (4) of each player's standing rocks per zone into storm rocks (user asked 2026-10-16; before that, rocks already up were never storm rocks) and sends `RockWeatherSet(id, weather)`; the client sets the rock's `Weather` attribute and `WeatherController` watches that attribute, so the emitters and label appear on rocks that are already up. Checked in Play: Eclipse gave 20 storm rocks (4 × 5 zones), all labelled, and none were left after it ended. The Diamond Rock is not boosted. Storm rocks also carry the modifier name above their name label (user asked 2026-10-16): `WeatherController` clones the `UI_RockLabel` template, keeps only `NameLabel`, gives it the modifier's `LabelTop`→`LabelBottom` gradient and a darkened stroke like the pedestal Modifier line, and stacks it `RockLabelHeightStuds` (2) tall right above the rock label as `WeatherLabel`. It goes with the emitters when the event ends or the rock breaks. The user approved the look in Play 2026-10-16.
- **Catching** (reworked 2026-10-16): once a minute during an event, each player rolls once: chance = `CatchChance` (2.5%) + `StormHitCatchChance` (1%) per storm-rock hit since the last roll (`WeatherService:RecordHit`, every non-crack chop), capped at `MaxCatchChance` (25%); all three halved 2026-10-16 (user: modified Roks stacked up too much cash). On a success one random placed Rok whose modifier the event's beats catches it, so at most one Rok per player per minute. Hit counts reset at each roll and each event start. Offline players catch nothing.
- **Hatching:** a geode cracked during an event has `HatchChance` (25%) to hatch with the modifier (`WeatherService:RollHatchModifier` → `PetService:Grant(..., modifier)` → `GeodeHatched` carries it).
- **Value:** `RokModifier.Rate` = base $/s × multiplier. Multipliers since 2026-10-16 (nerfed from 1.5/2/2.5/3/5 because pet income flooded cash): Dusty x1.25, Windy x1.5, Toasty x1.75, Zappy x2, Eclipsed x3. Storm-rock `RockMultiplier` (chop pay) is separate and unchanged. Used by pedestal earnings, offline income, Equip Best, tooltips and `RokValue.Sell`.

## Where things live
- Shared: `Config/WeatherConfig` (events, looks, modifiers, texts, attribute names), `WeatherClock`, `RokModifier` (Get, Multiplier, Rate, Name "Zappy Bloky", Tint, IsBetter), `NumberFormat.Rate` (one decimal under 1,000, so x1.5 rates read "$1.5/s").
- Server: `WeatherService` ticks every second and publishes Workspace attributes `Weather` (key or ""), `WeatherStartedAt`, `WeatherEndsAt`, `NextWeatherAt` (server time). It sends the 1-minute warning, start and end notices. Every weather notice (those three and the catch notice) uses the kind `Weather_<Modifier>` (`NoticeKindPrefix`; `NotificationConfig` registers one per modifier), and the `Notifications` screen gives those a top-to-bottom `LabelTop`→`LabelBottom` text gradient and a dark stroke (user asked 2026-10-14). Admin overrides: `Force(key)`, `EndActive()`, `StartIn(seconds)`; an ended or overridden natural slot is suppressed until its own end.
- Data: `Pet.Modifier` (already in the schema). `PetService:SetModifier(player, petId, modifier, isCatch)` writes it, re-syncs tools, fires `ModifierChanged` (PedestalService refreshes and re-banks the rate), and notifies "Bloky caught Zappy! $1/s → $3/s".

## Gotchas
- Rain streaks need a negative `Squash` (-3) with `VelocityParallel`; positive Squash made the 2026-10-14 rain fall as sideways dashes.
- Lightning 75-250 studs away must be very bright (Beam Brightness 25): at 5-6 the Thunderstorm atmosphere swallowed it. Big camera-facing cloud sprites overhead hung down over the view and hid the bolt; a flat cloud ceiling (VelocityPerpendicular) fixed it. A Beam `ZOffset` of 15 made the bolt's top vanish.
- Beam textures run vertically here (vfx `LESSONS.md` 11, re-confirmed 2026-10-15): the kit's horizontal lightning strips had to be rotated 90°.
- Rocks get particles only, no tint: Rush paints the rock gold and fades back to its own saved colour, so a tint would fight it.
- The skybox is a texture, so the sky colour only shifts through Atmosphere and ColorCorrection; the Eclipse sky still reads bluish.
