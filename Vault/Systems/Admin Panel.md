# Admin panel

The user asked for one place to keep every admin command, including future weather events and spawning. On 2026-10-08 they said reaching a point in the game to test one feature took too long, so it was rebuilt around presets, warps and commands that take a value (phase 1 of the plan; phases 2 and 3 are in [[To Do]]).

- **Who is admin:** everyone in Studio, plus the UserIds in `AdminConfig.UserIds` on live servers (since 2026-10-15: 467512659 = the user, 169380679 = co-dev, added so Team Test, which runs on a live server where `IsStudio()` is false, has the panel; remove or keep deliberately before public release). `AdminService` sets the player attribute `IsAdmin` and **checks admin rights again on every command**; the client attribute only shows the UI.
- **Opening it:** an "Admin" TopbarPlus icon (only shown to admins) toggles `StarterGui.AdminPanel` (red header, non-modal, top right). The panel is 600 wide and fills the screen height minus 16px margins (`Size` 0,600 by 1,-32), capped at 760 by a `UISizeConstraint`; a fixed 760 ran off the bottom of an 818px Studio viewport. Tabs come from `AdminConfig.Tabs`: Presets, Move, Stats, Roks, Chop, Weather, Debug. `List` is a ScrollingFrame. The `Tabs` grid is 4 columns (`CellSize` 0.25,-9 by 44) since the Weather tab made 7 tabs; 3 columns pushed Debug onto a third row over the first command.
- **Row kinds** (`Kind` in `AdminConfig.Commands`): `Button` (cloned from `CommandTemplate`), `Number` (`NumberTemplate`: an `Input` TextBox plus `Run`; Enter also runs), `Choice` (`ChoiceTemplate`: `Prev` / `Value` / `Next` cycler plus `Run`). Rows are named by command Id (`Preset_<Id>` and `Warp_<Label>` for those), so tests can click `AdminPanel.Panel.List.<Name>`.
- **Numbers** are parsed on the server (`AdminService/Arguments`): commas and spaces are ignored, and `k`, `m`, `b`, `t` suffixes work (`1.5m`). Ranges are checked per command.
- **Presets** (`AdminConfig.Presets`) wipe the save (like Reset) and then set cash, level or strength, rebirths, aura tier, slots, geodes, Roks (placed on pedestals in unlock order) and optionally a complete Index. Drafts: Fresh Start, Pre-Rebirth, Rebirth Ready, Desert, Late Game. Applied through `DataService:ResetData(player, overrides)`, which re-fires `PlayerLoaded` so every service resyncs. `ResetData` lists every progress field by hand and also clears `Receipts`; Settings are kept. A new saved progress field must be added there too. `TrainingTier` was missing until 2026-10-16, so Robux-bought stands survived a reset.
- **Auto preset:** in Studio only, set the string attribute `AdminAutoPreset` on Workspace (Edit mode) to a preset Id, e.g. `Desert`. The server applies it on your first load each Play. Clear the attribute to keep your real save. Studio has API access, so data otherwise persists between Plays.
- **Warps:** parts inside `Workspace.AdminWarps` (a Model with `ModelStreamingMode` Persistent, so the client sees them all under streaming). Each part's `Label` attribute is the button text and `Order` sorts them; the player lands on top of the part facing its front. "My Base" is added by code (the plot's `BaseSpawn`). To add a warp, drop in a part; no code change. Current: Lobby (42, -227.29, halfway between the shops and the forest gate), Geode/Sell/Cannon/Aura Shop (7 studs out from each pad, facing the stall; Cannon Shop warp added 2026-10-20 and the stalls rearranged by the user to face each other across the centre aisle: Geode (27.65, -269.36), Sell (27.65, -285.36), Aura (56.35, -269.36), Cannon (56.35, -285.36); lobby cannon at (42, -301)), Forest, Desert, Jungle, Ocean, Snow. Moved to the shrunk lobby 2026-10-18; the Arm Shop warp was deleted with the shop.
- **Shortcuts:** Ctrl+Shift + the command's `Shortcut` key, `Button` commands only (C cash, P Rok, G geode, M master, H next hatch Secret, K spawn spots, Backspace reset, N weather in 10 s), handled by `AdminController`.
- **Adding a command:** add `{ Id, Label, Tab, Kind, Default?, Placeholder?, Choices?, Shortcut? }` to `AdminConfig.Commands` and a handler with the same Id in `AdminService/Commands.luau`. The handler gets `(context, player, argument)` and calls the owning service's public method (e.g. `StatsService:SetStrength`, `AuraService:SetTier`, `PedestalService:SetSlots`, `RockService:ForceNextMaster`). Commands act on the caller unless they take a player argument.
- **`Text` rows** reuse `NumberTemplate` (same Input + Run) but the server reads the argument as text; `Placeholder` sets the TextBox's PlaceholderText.
- **Acting on other players (2026-10-19):** `AdminService/Targets.Find(text)` picks a player in this server by exact name or UserId first, then a unique name or display-name prefix (a leading `@` is ignored); several matches ask for more of the name. `Targets.Resolve(text)` falls back to any Roblox user: a number is a UserId, anything else is looked up with `GetUserIdFromNameAsync` (full username, no prefixes).
- **Reset Player Data** (Debug tab, `ResetPlayerData`, bar alias `reset`): type a name or UserId, Run once to arm, Run again on the same UserId within `AdminConfig.ResetConfirmSeconds` (5 s). In this server it calls `DataService:ResetData` and the target gets a "your data was reset by …" notification. Otherwise `DataService:ResetOfflineData(userId)` opens their profile (`Player_<UserId>`), resets the same fields as `ResetData` (shared `resetValues`), clears Receipts, keeps Settings and ends the session. If they are playing in another server, opening the profile makes that server end its session, which kicks them ("Your data session ended"). A UserId with no save is refused, so no empty profile is created. Studio only reaches `PlayerData_Studio`; to reset a real save, run it from Team Test or a live server. Pending confirms live in `context.PendingResets` (keyed by admin, holding the UserId). Tested 2026-10-19 on a seeded throwaway `Player_1` Studio save, which was then removed.
- **Reset Tutorial** (Debug tab, `ResetTutorial`, bar alias `tutorial`, 2026-10-21): Choice of All / Main Tutorial / Cannon Hint; resets only that tutorial's step on the caller, keeping the rest of the save and the analytics `Furthest`. Each tutorial service has a `Reset(player)` (`TutorialService`, `CannonHintService`); the state machine then re-decides at once, so with Roks owned the main tutorial jumps ahead (use the Fresh Start preset for a full run). A new tutorial = a choice in `tutorialChoices` (AdminConfig) + its service in `tutorialServices` (Commands.luau) + a `Reset` method.
- **Tabs since 2026-10-19:** Presets, Move, Stats, Roks, Index, Chop, Weather, Debug (8 tabs = two rows of 4).
- **Testing-speed commands (2026-10-19):** Roks: Grant Rok (pick any Rok), Rok: Set Trait (max value by default), +10 Geodes of a chosen type, Next Hatch (any rarity), Fill Backpack (rolls the zone geode up to `PetConfig.MaxPets`), Clear Backpack (removes every Rok not on a pedestal, no cash), Fill All Pedestals (unlocks every slot, Equip Best, rolls Roks for any empty slots). Index: Complete / Reset per page/zone or All (reset also clears that zone's claims), Claim All. Chop: Next Chop quality (Bad..Perfect, once), toggles Always Perfect / One-Hit Break / Ignore Strength / Instant Respawn (per player, in memory, cleared on leave), Spawn Rock (removes the farthest normal rock of that zone and spawns the chosen one near you), Set Hot Streak tier, Toggle Streak Freeze (refreshes the timer every `HotStreakConfig.AdminFreezeRefreshSeconds`). Stats: Grant All Cannons / Reset Cannons (2026-10-20, both unequip; aliases `cannons`, `nocannons`), Simulate Offline Hours (adds pad earnings as if you were away; still capped at `EconomyConfig.OfflineCapSeconds`, so more than 2 h gives the same as 2 h).
- **Rok target:** Set Trait and Give Modifier act on the held Rok, otherwise the newest Rok (highest id). Before 2026-10-19 Give Modifier fell back to the lowest-slot pedestal Rok.
- **Multi-word arguments:** handlers split the argument on spaces, and `Arguments.Match` accepts an exact or unique-prefix key, ignoring case. Choice rows send just the value, so the command bar can add a count: `rok nesty 3`, `geodes desert 25`, `trait luck 0.1`.
- **Command bar:** Ctrl+Shift+Space opens `StarterGui.AdminCommandBar` (screen `Screens/AdminCommandBar`). Type `<alias> <argument>`, then Enter. Each command's `Alias` is in `AdminConfig.Commands`, and `CommandBar.Extras` adds `preset <id>` and `warp <label>`. Aliases and choices accept unique prefixes (`warp des`). Hints list matching commands or the choices; Up/Down recall history; Esc closes; an unknown command keeps the bar open. A new command needs an `Alias` to be typed.
- **Snapshots:** Save / Load / Delete / List Snapshot (Debug tab, or `save name`, `load name` in the bar). They are stored in the DataStore `AdminSnapshots_Studio` (`AdminSnapshots` on live servers), one key per UserId, at most 20 per player. Names are up to 20 letters, digits, `-` or `_`. A snapshot holds the same progress fields `ResetData` resets (listed in `AdminService/Snapshots.luau`; a new progress field goes there too). Load checks it with `PlayerData.Validate`, then applies it through `ResetData`. The user's Studio save is in a snapshot named `beforetest` (2026-10-19).
- **Rule:** every new system ships with its admin commands (spawn it, force it, skip its timer), so the panel keeps up with the game.
- Everything goes through one packet, `AdminRun(commandId, argument)`; the argument is `""` for buttons.
- The pre-tabs panel is backed up as `ServerStorage.UIBackup.AdminPanel_PreTabs`.
