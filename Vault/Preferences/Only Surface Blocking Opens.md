When the user asks "what's on the to do list" or "what's open," do not enumerate every [OPEN]/[TBD]/[PROPOSED] tag in the [[Master Game Plan]]. Surface only items that actually block the current code work.

Most speculative/post-MVP questions (post-cosmic-tier content, offline cap tuning, index rewards, exact rebirth reset scope, daily vs. weekly rewards, PvP arena scope, random events, etc.) are either content-update questions the user will resolve as they come up, or "plainly obvious to just keep increasing later" (their words, 2026-09-27).

**Why:** after ~15 open items were dumped in one turn, the user said "there's so many questions that don't actually matter right now or are plainly obvious to just keep increasing later."

**How to apply:**
1. When asked what's pending, name only items that (a) block a code task about to happen, (b) the user has asked about specifically, or (c) affect a decision the user is actively making.
2. If a batch of [OPEN] items comes up in one exchange, close them by writing a Decision Log entry rather than re-listing them next time.
3. Do not restate resolved items or things the plan already marks [PLAYTEST]/config-driven.
4. When the user defers something, treat it as closed until they raise it; don't nudge.
5. This doesn't loosen [[Code Output Rules]] on player-facing decisions (still propose-and-wait).
